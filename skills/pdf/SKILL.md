# PDF Generator

Generate a PDF from any content source and deliver it directly to the user. No external services — everything is rendered locally.

## When to Use This Skill

- "Generate a PDF from this file"
- "Export this as a PDF"
- "Save this as a PDF"
- "Convert this markdown / HTML to PDF"
- "Create a PDF report on [topic]"
- "Make a printable version of this"
- "Download this as a PDF"

## What This Skill Does

1. **Identifies the content source** — file path, inline text, or current working file
2. **Selects the best available renderer** — pandoc (preferred) → weasyprint → wkhtmltopdf
3. **Renders the PDF locally** with sensible defaults (1 in margins, 12 pt body, syntax highlighting for code)
4. **Verifies the output** — confirms the file exists and is non-empty before delivery
5. **Delivers the file** — sends via `SendUserFile` with a short caption; cleans up any temp files
6. **Handles errors gracefully** — shows the relevant stderr lines and suggests a fix if rendering fails

## Renderer Reference

| Priority | Tool | Best for | Install |
|----------|------|----------|---------|
| 1st | `pandoc` | Markdown, plain text, RST | `apt install pandoc` / `brew install pandoc` |
| 2nd | `weasyprint` | HTML + CSS | `pip install weasyprint` |
| 3rd | `wkhtmltopdf` | Complex HTML layouts | `apt install wkhtmltopdf` |

**pandoc command** (markdown → PDF):
```bash
pandoc input.md --pdf-engine=xelatex -V geometry:margin=1in -V fontsize=12pt -o output.pdf
```

**LaTeX fallback chain**: xelatex → pdflatex → lualatex → weasyprint

**weasyprint command** (HTML → PDF):
```bash
weasyprint input.html output.pdf
```

**wkhtmltopdf command** (HTML → PDF):
```bash
wkhtmltopdf --enable-local-file-access input.html output.pdf
```

## Output Path Convention

| Situation | Output path |
|-----------|-------------|
| Source is `path/to/report.md` | `path/to/report.pdf` |
| Project has a `dist/` directory | `dist/<title>.pdf` |
| Inline content, no project | `./output.pdf` |

## Error Handling

| Error | Action |
|-------|--------|
| No renderer available | List install commands per OS; stop and ask user |
| LaTeX engine missing | Retry with next engine in fallback chain |
| Render exits non-zero | Show last 20 lines of stderr; suggest fix |
| Output is 0 bytes | Treat as render failure; show stderr |

## Tips

- Markdown + pandoc + xelatex produces the highest-quality PDFs — install `texlive-xetex` for best results
- For HTML with custom fonts or CSS layouts, use weasyprint and pass `--base-url` to resolve local assets
- Write content to a temp file first if it's inline text with no source file
- Temp files go in `/tmp` and are deleted after delivery — never left in the project directory

## Constraints

- Never upload the PDF to any external service — deliver only via `SendUserFile`
- Never install packages without the user's explicit approval
- Sensitive content: remind users to handle the output file carefully if they flagged it as private

## Common Use Cases

- Exporting markdown documentation to share with non-technical stakeholders
- Converting HTML reports generated by analysis scripts to printable PDFs
- Archiving conversation output or generated content as a portable file
- Preparing submission-ready documents from structured markdown outlines
- Turning code listings into syntax-highlighted PDF references
